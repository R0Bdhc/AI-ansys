# 项目监听 + LLM 交互面板（含实时性分级策略）

## 前置评估结论（已确认方向）

不追求 1s 级高实时。**分级实时**：活动 job 保留现有 1s watcher（求解生命周期内、目录小、成本可控）；新增的被动项目监听默认 5s 可配 + **静默退避**（无变化自动拉长间隔至 60s 上限，有活动立即恢复）+ **稳定触发**（文件停止增长 10s 或出现求解终止标记才标记"可分析"，避免对半截日志反复分析）。读取便宜、LLM 调用才贵，稳定触发从根上控制成本。

## 一、新增 `folder_monitor.py`（被动项目监听）

- `FolderMonitor`：单监听器后台线程
  - 扫描：`os.walk` 有界递归（默认深度 3，可配），跟踪 `*.out`/`*.err`（可扩 glob）
  - 增量采集：按文件字节偏移只读新增部分，复用 `BlockStreamParser` 增量解析诊断块（CRLF/块头缩进已归一化）
  - 分类：复用 `ERROR_PATTERNS`/`WARNING_PATTERNS`，去重计数（同 solve_watcher 签名逻辑）
  - 事件：每类事件实时写入 observability（kind=`monitor_event`，带 monitor_id/文件/级别/代码/计数）→ 仪表盘日志面板直接可见
  - 稳定触发：文件 10s 无增长或出现 `ROUTINE COMPLETED` → 标记"待分析"并记录错误摘要快照
  - 静默退避：整个监听树 10 分钟无变化 → 轮询间隔翻倍至 60s 上限；任何活动立即恢复
- `FolderMonitorManager`：线程安全注册表 + 配置持久化 `runtime_data/monitors.json`（服务重启自动恢复监听）
- `__main__` 自测：合成目录渐进写入，验证发现/增量/稳定触发/退避

## 二、main.py 新端点（7 个）

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/monitors` | 创建监听 `{path, interval?, depth?, auto_analyze?}`（校验目录存在） |
| GET | `/monitors` | 监听列表（状态/文件数/事件计数） |
| DELETE | `/monitors/{id}` | 停止并移除监听 |
| GET | `/fs/browse?path=` | 只读列目录（子目录 + 各目录 .out/.err 计数），供前端选择项目 |
| POST | `/llm/test` | LLM 连通性强刷测试（force_refresh） |
| POST | `/monitor-analyze` | 人工触发：对监听文件执行 LLM 分析（`{monitor_id, file}`） |
| （自动） | — | `auto_analyze=true` 的监听器在稳定触发时自动调 `analysis_pipeline.analyze_execution`，报告路径进事件 |
